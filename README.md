# HelpFlow

Веб-застосунок для обробки звернень служби підтримки (helpdesk). Клієнти подають звернення через власний портал, система автоматично розподіляє їх між агентами за навантаженням, контролює терміни SLA та ескалує прострочені звернення.

## Основні можливості

- реєстрація та автентифікація (JWT) з ролями client / agent / admin;
- клієнтський портал: створення звернень, перегляд статусу власних звернень;
- автоматичне призначення звернення агенту з найменшим поточним навантаженням;
- автоматичний розрахунок дедлайну SLA за категорією та ескалація прострочених звернень;
- Kanban-дошка звернень для агентів/адміністраторів із фільтрами;
- публічні коментарі та внутрішні нотатки з розмежуванням видимості за роллю;
- керування категоріями та користувачами (адміністратор).

## Системні вимоги

- Python 3.11+
- Node.js 18+
- PostgreSQL 14+ (опційно для локальної розробки — достатньо SQLite)

## Встановлення backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate      # Linux/macOS
.venv\Scripts\activate         # Windows

pip install -r requirements.txt
cp .env.example .env
```

Налаштування бази даних (міграції):

```bash
flask db upgrade
```

## Встановлення frontend

```bash
cd frontend
npm install
cp .env.example .env
```

## Змінні середовища

**backend/.env**

| Змінна | Опис | Приклад |
|---|---|---|
| `DATABASE_URL` | рядок підключення до БД | `postgresql://user:password@localhost:5432/helpflow` (або `sqlite:///helpflow.db` для локальної розробки) |
| `JWT_SECRET_KEY` | секретний ключ для підпису JWT | випадковий довгий рядок |
| `FLASK_ENV` | середовище виконання | `development` / `production` |

**frontend/.env**

| Змінна | Опис | Приклад |
|---|---|---|
| `VITE_API_BASE_URL` | адреса backend-API | `http://localhost:5000/api` |

## Запуск у режимі розробки

Backend:
```bash
flask run
```

Frontend:
```bash
npm run dev
```

## Опис API

Повний перелік ендпоінтів — у технічному завданні (`docs/HelpFlow_TZ.md`, розділ AC-06). Основні групи:

| Група | Базовий шлях | Призначення |
|---|---|---|
| Auth | `/api/auth` | реєстрація, вхід |
| Tickets | `/api/tickets` | створення та керування зверненнями |
| Comments | `/api/tickets/<id>/comments` | публічні коментарі та внутрішні нотатки |
| Categories | `/api/categories` | категорії звернень та їх SLA |
| Users | `/api/users` | керування користувачами (адміністратор) |

## Приклад типового сценарію

1. Клієнт реєструється та подає звернення через `POST /api/auth/register` → `POST /api/tickets`.
2. Система автоматично призначає агента з мінімальним навантаженням і обчислює `sla_deadline`.
3. Агент бачить звернення на Kanban-дошці, бере його в роботу (`PATCH /api/tickets/<id>`, статус `in_progress`).
4. Агент та клієнт обмінюються коментарями (`POST /api/tickets/<id>/comments`); агент додатково залишає внутрішню нотатку, недоступну клієнту.
5. Агент позначає звернення вирішеним; якщо дедлайн SLA порушено раніше — система вже підвищила пріоритет автоматично.
